## 1. Schematic Design

### 1.1 External Circuit Requirements for the Minimal System

#### 1.1.1 DDR Circuit Design

- Supports LPDDR4 / LPDDR4x.
  Pulling **DDR_LP4x_SEL** down to GND selects **LPDDR4 mode**; pulling it up to **AVDD18_DDR** selects **LPDDR4x mode**.
- The LPDDR4/4x external ZQ resistor must be **240 Ω ±1%**, connected to GND.

![](./static/XZHWbMYUNol3PuxGJWTcMh6Nnnb.jpg)

**Note:**
**DDR routing must strictly follow the reference design provided by our company. Please refer to the hardware section in the release package for the official design files.**

#### 1.1.2 Reset

- Hardware reset of the chip is controlled externally and is active low.
- Add a **10 nF capacitor** to the pin to suppress jitter and enhance noise immunity, preventing false resets.
- The pull-up supply for the **RESET_IN_N** net must match the IO power domain (i.e., pull up to **VCC18_GPIO**).
- The **PGOOD** signal from P1 connects directly to **RESET_IN_N** on K1, supporting push-button reset for both K1 + P1.
- If shared with other reset sources, add an **OR gate** or **diode isolation**.

![](static/L6Drbn4aWoFurexWkvfcNLCynKd.jpg)

#### 1.1.3 JTAG Interface

- Supports **Primary JTAG** and **Sec2 JTAG**.
- TDI, TMS, TCK, TDO, and Power/GND must connect to a J-Link debugger (signal voltage must match the Power domain).
  TRSTn should connect to the J-Link debugger or be pulled up to Power.
- When using Sec2 JTAG, pull up **JTAG_SEL**.
- Sec JTAG supports **X60 / N308 CPU**, controlled via **MMC1_SD_CMD**.

![](static/P1hUbOqj6oygc8xxYtScqTbcnec.jpg)

#### 1.1.4 Power Management (PMIC) Circuit Design

- P1 input supply is recommended to be **4V**.
  Vin3/Vin4 and Vin5/Vin6 must follow the reference PCB isolation guidelines.
- Add 220pF capacitors by default to **SW3–SW6**.
- The **FB** and **FBGND** pins of BUCK1/2 must connect directly to the main controller’s FB/FBGND pins.
  Keep routing away from noise-sensitive signals.

![](static/Z9NxbQDzcous9ixm2dYcNILnnnc.jpg)

**The P1 peripheral circuits must strictly follow our reference design. Please see the hardware files included in the release package.**

#### 1.1.5 Hardware Initialization and System Configuration Straps

|-------------|-----------|----------------|
| QSPI_DATA3 / Strap3 FDL         | I         | Boot / Download selection<br>0: Boot<br>1: Download                         |

#### 1.1.6 Clocking Circuit

The system clock is generated by the internal feedback circuitry in combination with an external **24 MHz crystal oscillator**.

- Load capacitors must follow the crystal oscillator datasheet; **12 pF recommended**.
- Reserve a **1 MΩ resistor** in parallel between XIN and XOUT.

![](static/RLBTb8UAyohJMfxjP9ociWWJnrh.jpg)

**Note:**
Ensure the chosen capacitors match the crystal’s load requirement. Use **NPO dielectric**.
A **4-pin SMD crystal** is recommended; connect the two GND pins solidly to the PCB ground to improve ESD robustness.

#### 1.1.7 FLASH Schematic Design

- Quad-SPI serves as the interface for external serial flash with up to four bidirectional data lines.
- The Flash controller supports **SPI NOR Flash** and **SPI NAND Flash**.
- Supports **1.8V / 3.3V Flash**; follow configuration based on **VCC1833_QSPI** power domain.
- Quad-SPI’s four data pins are multiplexed with system configuration straps.
  Fly-by routing is recommended. See **Section [1.1.5 Hardware Initialization and System Configuration Straps]**.

![](static/XAfAbsI1Aom0A4x1SR1cXpbEnjg.jpg)

> **Note:**
> No extra pull-ups are required for Flash data signals—internal configuration is already provided.
> Because the data pins are shared with boot straps, apply pull-up or pull-down resistors as required by your system configuration.
> See **Section [1.1.5 Hardware Initialization and System Configuration Straps]** above.

#### 1.1.8 eMMC

- Compatible with **8-bit eMMC 5.1** specification.
- eMMC card supports **SPI mode**.
- External pull-ups/pull-downs for Data and DS are recommended as placeholders; mark as NC in mass production.
- Pay attention to **length matching** during layout.

![](static/JLpAb0XWWoT3J3xUQ1ZcwrtMngd.jpg)

### 1.2 Power Design Recommendations

#### 1.2.1 CORE Power Design

The typical core voltage is **0.9 V to 1.05 V**. Actual voltage is dynamically regulated by the **remote-sense dynamic voltage adjustment circuit** inside P1.
P1 **BUCK1 and BUCK2 must be combined** to supply the core rail.

The number and value of filtering capacitors have been verified through PI simulation. **Follow the latest schematic exactly—do not modify these components.**
Refer to the latest K1 schematic for details.

#### 1.2.2 DDR Power Design

K1 supports **LPDDR4 / LPDDR4x**, with typical voltages **1.1 V / 0.6 V**.
The DDR devices and the K1 DDR IO power must use **the same power network**.

As with the core rail, the number and value of filtering capacitors have been validated through PI simulation. **Follow the latest schematic without changes.**
See the latest K1 schematic.

#### 1.2.3 IO Power Design

- Pins named **VCC18_GPIO** must be supplied by a **1.8 V digital power rail**.
- Pins named:

  - **VCC1833_GPIO2** (GPIO75–80)
  - **VCC1833_GPIO3** (GPIO47–52)
  - **VCC1833_MMC1** (MMC1_DAT0–3, CMD, CLK)
  - **VCC1833_QSPI** (QSPI_DAT0–3, CLK, CS1)
    should be powered by **3.3 V or 1.8 V**, depending on the peripheral device being used.
- A **0.1 µF + 1 µF** capacitor pair must be placed near the VCC1833_GPIO2, VCC1833_GPIO3, VCC1833_MMC1, and VCC1833_QSPI pins, as shown below.

![](static/Az7LbCdIaoQh81x1ByHcf40Anuf.jpg)

**Note:**

- **GPIO90** configures the default QSPI operating voltage:

  - When GPIO90 is **pulled up to 1.8 V**, **VCC1833_QSPI must operate at 3.3 V**.
  - When GPIO90 is **pulled down to GND**, **VCC1833_QSPI must operate at 1.8 V**.
- **Unused GPIO pins may remain floating**, but **each GPIO group’s power rail must still be supplied**.
  Modules such as **HDMI, PCIEA/USB3.0, PCIEB, PCIEC, MIPI CSI, eMMC, USB2.0, MIPI DSI**, etc., must also remain powered even if not used.

#### 1.2.4 PLL Power Design

K1 includes **two PLL power rails**:

- **AVDD09_PLL**: Must be isolated using a ferrite bead (**120 Ω @ 100 MHz, DC resistance ≤ 0.07 Ω**).
  (This ferrite bead spec applies to all similar cases below.)
- **AVDD18_PLL**: Must also be isolated from the 1.8 V rail using a ferrite bead.

Refer to the latest P1 schematic.

#### 1.2.5 Power-Up/Power-Down Sequencing

Core, DDR, and IO power rails follow specific sequencing requirements controlled by the **PMIC P1**.
Refer to the latest schematic.

![](static/ALCHbLyAHoJWKvxCjDncuhBon2J.jpg)

#### 1.2.6 Remote-Sense Dynamic Voltage Scaling

- The K1 core power rail **must** support **dynamic voltage scaling (DVS)**, enabling real-time adjustment of the DC-DC output.
- **VDD09_CORE_B_FB** must route from the main controller’s **VCC_M1_FB** ball, and
  **VDD09_CORE_B_FBGND** must route from **VSS_FB**.

![](static/ZugrbJ9AToC7h3xoXAecvIGjnVa.jpg)
![](static/JhUub5J8boHJJNxATRXclCrWn2c.jpg)

### 1.3 Analog Interface Design Guidelines

#### 1.3.1 Analog Audio Interface Design

- The audio module’s analog power rails (**AUD_VDDU09, AVDD18_AUD, AVDD33_AUD**) **must be isolated from the system power rails using ferrite beads** (recommended **120 Ω @ 100 MHz**).

#### 1.3.2 I2S Interfaces

- K1 supports **four I2S interfaces**.

  - **I2S0 / I2S1** are controlled by the main CPU (**X60**).
  - **R_I2S2 / R_I2S3** are controlled by the RCPU (**N308**).
- Each I2S interface can be configured as either **master** or **slave**.

#### 1.3.3 MIPI CSI RX Interface Design

The differential video input supports **4-lane + 4-lane** or **4-lane + 2-lane + 2-lane** configurations.
In **4 + 2 + 2 mode**, three cameras can stream simultaneously. However, the ISP can only process **two** streams; the third stream can only output **YUV or RAW** data directly through the **CCIC DMA** into DDR—**it cannot be processed by the ISP**.

- **MIPI CSI1**
  Four differential data pairs sample against the **MIPI_CSI0_CK1XP/N** differential clock.

- **MIPI CSI2**

  **[2-lane mode]**
  Differential pairs **MIPI_CSI3_D2P/N** and **MIPI_CSI3_D3P/N** sample against the **MIPI_CSI2_CKP/N** differential clock.

- **MIPI CSI3**

  **[2-lane mode]**
  **MIPI_CSI3_D0P/N** and **MIPI_CSI3_D1P/N** sample against **MIPI_CSI3_CKP/N**.

  **[4-lane mode]**
  Four pairs (**D0P/N, D1P/N, D2P/N, D3P/N**) sample against **MIPI_CSI3_CKP/N**.

Power requirements:

- **AVDD09_CSI** must be isolated from the digital power rail using a ferrite bead; place **two 1 µF capacitors** near the chip pins.
- **AVDD18_CSI** must also be isolated with a ferrite bead; place **one 1 µF capacitor** near the chip pins.

#### 1.3.4 MIPI DSI TX Interface Design

- K1 integrates one **MIPI TX PHY** for connecting to MIPI-based LCD panels.
- **AVDD18_DSI** must be isolated from the digital power rail using a ferrite bead.

Refer to the latest K1 schematic for detailed design.

#### 1.3.5 SPI LCD Interface Design

- Supports **1-wire serial peripheral SPI display data transfer**.
- Data pin is **SPILCD_DOUT0** or **SPILCD_DIN**.

**Note:**
The **LCD_TE** signal **cannot** be used simultaneously for both SPI LCD and MIPI DSI LCD.

#### 1.3.6 HDMI Interface Design

- K1 includes an integrated **HDMI PHY**.
- HDMI power rails (**AVDD33_HDMI, AVDD18_HDMI**) must be isolated from the digital power rails using ferrite beads.

  - Place **two 1 µF capacitors** near the chip pins.
  - **AVDD33_HDMI** must be supplied through a **MOSFET switch circuit**, with two 1 µF capacitors near the pins.
- HDMI signals require **ESD protection**. ESD components must be placed close to the HDMI connector with **parasitic capacitance < 0.3 pF**.
- **HDMI_SCL, HDMI_SDA, HDMI_CEC, HDMI_HPD** require external circuitry:

  - **HDMI_SCL / HDMI_SDA** must be level-shifted to **5 V**
  - **HDMI_CEC** must be level-shifted to **3.3 V**
  - Incoming **HDMI_HPD** must be level-shifted to **1.8 V** before entering the SoC
    (See the figure below for the specific design.)

![](static/JLRxbInSAoBjMjxvI6pcW9wBnPu.jpg)

For complete schematic details, refer to the official K1 schematic design files.

### 1.4 Peripheral Interface Design Guidelines

#### 1.4.1 USB 2.0

- K1 provides **three USB 2.0 ports**, with **USB2.0-0** and **USB2.0-2** supporting **OTG**.
- **USB2.0-0** serves as the **Download interface**.
- **AVDD33_USB** should connect to the system 3.3 V power via a **3.3 Ω resistor**, with **three 0.1 µF capacitors placed near the pins**.

![](static/T847b1iYiolnurxSinxcbrjDnvg.jpg)

- **ESD protection** is required on USB2.0 signals. The ESD device parasitic capacitance should be **< 1 pF** and placed close to the USB connector.

#### 1.4.2 PCIe

- K1 provides **three PCIe ports**:

  - **PCIEA X1**
  - **PCIEB X2**
  - **PCIEC X2**
- Power rails **AVDD09_PCIEA, AVDD09_PCIEB, AVDD09_PCIEC** should be combined and isolated from the system power using ferrite beads; place **three 1 µF capacitors near each pin**.
- Power rails **AVDD18_PCIEA, AVDD18_PCIEB, AVDD18_PCIEC** should be combined and isolated from digital power using ferrite beads; place **three 1 µF capacitors near each pin**.

**Note:** Regardless of which PCIe is used, **PCIEA_R_EXT must always be pulled up to AVDD09_PCIE via a 240 Ω 1% resistor**.

- **PCIE_RXP/N**

  - If connecting to an **IC**, each RX differential pair must include a **220 nF series capacitor at the IC side**.
  - If connecting to a **PCIe slot**, the RX differential pairs connect directly without series capacitors.
- **PCIE_TXP/N**

  - Each TX differential pair must include a **220 nF series capacitor at the K1 side** for AC coupling.
- **PCIE_REFCLKP/N** supports two clock schemes:

  1. **K1 provides the clock** to the device. Differential signals connect directly.
  2. **External device provides the clock** to K1. Differential signals at the device source must include a **49.9 Ω pull-down resistor**. Clock deviation tolerance: ±300 ppm, compliant with PCIe specification.

#### 1.4.3 UART

K1 provides **12 UART interfaces**, divided into **X60 UART** and **N308 UART**:

- **X60 UART**: 10 interfaces

  - UART0: 2-wire debug port
  - UART1–UART9: 4-wire ports; UART3 can be used for the **secure domain**
- **N308 UART**: 2 interfaces, currently unsupported; consult FAE if needed.

#### 1.4.4 I²C

K1 provides **10 I²C interfaces**, categorized into **AP I²C, HDMI I²C, PWR I²C**:

- **AP I²C**: 8 interfaces (**I2C0–I2C7**) for peripheral control; **I2C0, I2C1, I2C7** are used for camera control.
- **HDMI I²C**: 1 interface (**HDMI_I2C**) for HDMI interface control.
- **PWR I²C**: 1 interface (**PWR**) for power IC configuration.

#### 1.4.5 MMC

- K1 has **two MMC interfaces**:

  - **MMC1** supports **3.3 V / 1.8 V logic levels**
  - **MMC2** supports **1.8 V only**
- MMC1/2 can interface with **SDIO Wi-Fi** or **SD Cards**.

#### 1.4.6 USB 3.0

- K1 supports **one USB 3.0 port**, **shared with PCIEA**.
- **ESD protection** is required; device parasitic capacitance should be **< 0.5 pF** and placed close to the USB connector.
- Signal handling:

  - **USB3_RXP/N**

    - If connecting to an **IC or module**, series **100 nF capacitors** are required at the IC/module side.
    - If connecting to a **socket**, the differential pairs connect directly to the socket without series capacitors.
  - **USB3_TXP/N**

    - If connecting to an **IC or module**, series **100 nF capacitors** are required at the K1 side.
    - If connecting to a **socket**, series **100 nF capacitors** should be placed near the socket.

**Note:** Regardless of using **USB 3.0** or any **PCIe**, **PCIEA_R_EXT must always be pulled up to AVDD09_PCIE via a 240 Ω 1% resistor**.

## 2. PCB Design

### 2.1 PCB Stack-up Design

To minimize signal reflection during high-speed transmission, **impedance matching must be maintained** at the source, receiver, and along the transmission lines. The impedance of a single-ended trace depends on its **trace width** and **distance to the reference plane**. For differential pairs, trace width and spacing depend on the selected **PCB stack-up**.

Since **minimum trace width and spacing** are constrained by PCB type and cost, the chosen stack-up must satisfy all **impedance requirements**, including inner/outer layers, single-ended, and differential lines.

**Stack-up design principles:**

1. Layers adjacent to components should be **ground planes** to provide reference for routing.
2. All signal layers should be as close to ground planes as possible.
3. Avoid placing two signal layers adjacent to each other.
4. High-current power layers should be adjacent to ground planes if possible.
5. Stack-up should be **symmetrical**.

K1 currently uses a **6-layer stack-up**. The reference stack-up is shown below. If using another stack-up, recalculate impedance according to the PCB manufacturer’s specifications.

**6-layer reference stack-up:**

- Signal layers: **L1 / L3 / L4 / L6**
- Reference planes: **L2 / L5** (complete planes)

![](static/WlqIbKooioYfSrx2Ac7cUzrKnwf.png)

### 2.2 General Routing Guidelines

1. Avoid **right angles or sharp corners** in traces.
2. Keep traces away from **clock components** (crystals, oscillators, clock generators/distributors), **switching power supplies**, and **magnetic components**.
3. Ensure traces have **continuous reference planes**.
4. In **BGA areas**, connect separated planes using traces as shown:

   ![](static/QnCRbOxf5okUxTxkrDzcKCvXnPd.png)

5. Minimize stub lengths; recommended stub length is **0**:

   ![](static/WUJgbwo3HoRyjbxxEMicxpxUneg.png)

**High-speed signal routing recommendations:**

1. When changing layers, add **GND vias next to signal vias** to maintain a continuous return path:

   ![](static/H87TbNwt6o3R66xOBw9cUpYynsc.png)

2. Surface-mount pads reduce impedance; to mitigate discontinuities, **remove the reference plane under the pad**. Common SMD components: ESD devices, capacitors, common-mode chokes, connectors.

   ![](static/LQHQbrOjroTt0Nxcc9EcSRJwn4f.png)

3. Avoid **glass fiber weaving effects**:

- The dielectric constant varies locally due to glass fiber weave gaps, causing impedance fluctuations and skew in differential pairs.
- For interfaces ≥8 GT/s and trace length >1.5 in, glass fiber effects must be mitigated:

**Method 1:** Route traces at **10° angles** or rotate PCB material 10° during fabrication.

   ![](static/RHINb1HT4ovh29xhfgechPdSnNg.png)

**Method 2:** Use **Zig-Zag routing**; width **W ≥ 3× glass fiber spacing**. Recommended: W=60mil, θ=10°, L=340mil.

   ![](static/Jsv8bmUOXowHr9xTMK2co1YQnDe.png)

4. Minimize layer changes; if necessary, consider **Via Stubs** and keep them short.
5. Differential via recommendations (for 8 GT/s interfaces):
   Add **Dog-Bone structures**; optimize dimensions via simulation. Reference for EVB 1st-order HDI:

   - R Drill = 4 mil (Drill radius)
   - R Pad   = 16 mil (Pad radius)
   - D1      = 30 mil (differential via center spacing)
   - D2      = 15 mil (back-side pad size)
   - D3      = 30 mil (signal via to return via center spacing)

   ![](static/K5Qebfo2qoTAgJx3tmscDPgGnXf.png)

6. Differential pairs: **length mismatch ≤5 mil**. When routing compensation is needed, ensure **trace shapes minimize impedance discontinuities**:

![](static/Qq2kba5vSo149txneDBclEKMnkd.png)

### 2.3 Power and Decoupling Capacitor Design

1. Place **decoupling capacitors close to the pins**; use **short, thick traces** to vias for power and GND.
2. Power planes should be **short and wide**; avoid fragmentation by too many vias.
3. For proper **PI analysis**, use our reference capacitor selection; do **not reduce capacitor count**.
4. Via placement should follow our **reference design**, do not remove power or ground vias.

### 2.5 Subsystem Design

For a small system composed of **CPU – DDR – eMMC**, we strongly recommend using our **reference board design**, which has been fully simulated and verified. Designing your own board requires **strict simulation and verification**, and carries high risk.

#### 2.5.1 CPU – PCB Layout Recommended Design

1. **Outer CPU balls** can fan out on the top layer using **5mil traces**. The second row can route **between the first-row balls** using 5mil traces:

   ![](static/PR1Cbv7n9o5KRMx8mO6caAgin9c.png)

2. **Inner CPU balls**: if signals occupy the first and second rows, starting from the third row, **route to inner layers**. Place vias **regularly** to leave wide channels for ground and power planes. Copper fills on ground layers with multiple channels connected to the outer ground improve **SI/PI and thermal performance**:

   ![](static/VTmsbjlAToxHRGxic8ZcS3yjnSc.png)

3. **Power plane copper fills**: place vias systematically to maximize copper for each power net, improving **power integrity**:

   ![](static/OIPvbm5dooddZWxMKyZccErOnIb.png)

4. **Capacitor placement** on the CPU backside: place capacitors at relevant pins; add as many as possible where space allows to improve **PI**:

   ![](static/UrMbbAjMSotBZzxjjhVciqqWntf.png)

5. If trace routing is difficult near the CPU, temporarily reduce trace width using a **neck**, but restore to normal width after leaving the CPU area:

   ![](static/MaLGbIxYloUVwAxMcK7ckqDTnEd.png)

6. **Top-layer power and ground**: connect with **short, thick traces** as shown:

   ![](static/EGIibAEYUo8xNhxXCERcMZaTnl7.png)

7. **Core power feedback line**: route from the **farthest end of the power plane** with minimal layer changes.

#### 2.5.2 DDR – PCB Layout Recommended Design

For a **6-layer PCB**, DDR signals are recommended on **L1 and L4**, with primary references to **complete ground planes on L2 and L5**. Incomplete GND planes significantly degrade signal quality. Maintain **spacing and length requirements** as shown in the table. Include **pin_delay** during routing.

| Parameter                          | Requirement       |
| ---------------------------------- | ----------------- |
| DDR single-ended impedance         | 50Ω ±10%          |
| DDR differential pair impedance    | 90Ω ±10%          |
| Spacing between different bytes    | ≥ 3 × trace width |
| Spacing within a byte              | ≥ 2 × trace width |
| Differential pair P/N length match | ≤ 5 mil           |
| Same-byte group (CLK as target)    | ≤ 50 mil          |

**DDR design is challenging** due to high interface speed. Use our **DDR template and firmware**, which are validated by simulation and testing. If designing your own PCB, follow these guidelines and **simulate thoroughly before fabrication**:

1. **GND vias** at CPU and DDR ends must follow the template; do **not remove GND vias**:

   ![](static/JopHbW8dIoUcywxNv62c2dTmnSh.png)

   ![](static/SgEXbHZ4PovjlNxfy9ZccaSJnfg.png)

2. **Routing crosstalk affects signal delay**; for length-matched traces, maintain **S ≥ 3W**:

   ![](static/KbXZbOQnHoe5Jwxj5q6ckZ08n1c.png)

3. DDR IC area: **one GND via per pin**; add more vias if space allows.
4. Adjust via positions and optimize plane splits to improve **return paths**:

   ![](static/OALKboFmXo9MkrxQemDcu3WQn5e.png)

5. **Decoupling capacitors**: each pad should have at least one via. For **0603/0805 caps**, recommend **two vias per pad**, placed close to the pin to reduce loop inductance:

   ![](static/CH5bbSe7aoeVpHx48Recru9MnJd.png)

#### 2.5.3 eMMC – PCB Layout Recommended Design

- Maintain **CPU–eMMC spacing** according to the reference board.
- If space is limited, **minimize trace length** between CPU and eMMC, ideally ≤ **1500mil**.
- For **D0–D7, RE, WE**, ensure **length matching to CLK**, within ≤ **100mil**.

### 2.6 Interface PCB Design

#### 2.6.1 GMAC Signal PCB Design

- Keep GMAC traces **as short as possible** and minimize layer transitions. Trace requirements:

| Parameter                     | Requirement            |
| ----------------------------- | ---------------------- |
| Trace impedance               | Single-ended 50Ω ±10%  |
| Clock-to-data length matching | ≤ 100 mil              |
| Trace length                  | ≤ 4000 mil             |
| GMAC trace spacing            | ≥ 3 × GMAC trace width |

#### 2.6.2 SDIO Signal PCB Design

- Avoid **stubs** on all SDIO traces; all traces must **reference GND**.
- Number of layer transitions (VIA) for each trace: **≤ 4**.
- Surround each SDIO trace with GND for signal stability.
- Preferred: **CLK/CMD/DATA0-3 individually shielded**. If space is limited:

  - CLK & CMD separately shielded
  - DATA0-DATA1 together, DATA2-DATA3 together

| Parameter                     | Requirement            |
| ----------------------------- | ---------------------- |
| Trace impedance               | Single-ended 50Ω ±10%  |
| Clock-to-data length matching | ≤ 100 mil              |
| Trace length                  | ≤ 2500 mil             |
| SDIO trace spacing            | ≥ 3 × SDIO trace width |

> **Note:** WiFi module SDIO traces must strictly follow the hardware design guide for PCB layout. After PCBA assembly, send the board to the factory for **WiFi TX Delay tuning and testing**.

![](static/MgvUbH58IoxNfwxJANtcXLcjnVa.png)

#### 2.6.3 USB2.0 Signal PCB Design

| Parameter                 | Requirement           |
| ------------------------- | --------------------- |

| Max P/N delay mismatch    | ≤ 5 mil               |
| Trace length              | ≤ 5000 mil            |
| Differential pair spacing | ≥ 3 × USB trace width |

#### 2.6.4 USB3.0 Signal PCB Design

| Parameter                 | Requirement           |

## 3. System-Level ESD Design

- For the **24MHz system clock**, use a **4-pin SMD crystal**; connect the two GND pins fully to PCB ground to improve **clock EMI immunity**. Avoid routing signals under the crystal.
- During PCB layout, keep the **small subsystem away from metal interfaces** to enhance overall ESD performance.
- External connectors (AV I/O, USB, Ethernet, alarm ports) must have **ESD protection devices**.
- For **floating-ground systems**, avoid splitting ground under metal interfaces.
- **PCB mounting holes** should be metallized and connected to GND to ensure proper chassis grounding.
- For **grounded systems**, chassis must be connected to earth; connect protective and digital grounds at a **single point**, located away from small system circuits, preferably near the power connector.
- **Connector housings** should be metal and electrically connected to the chassis (e.g., HDMI, USB with screws; RJ45 with shielding tabs).
