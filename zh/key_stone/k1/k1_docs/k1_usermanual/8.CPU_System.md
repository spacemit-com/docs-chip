# 8. CPU 系统

## 8.1 概述

K1 的 CPU 系统由以下部分组成：

- 一个 SpacemiT® X60™ RISC-V 主 CPU（以下简称 **CPU 子系统**）
- 一个 RISC-V 实时 CPU（以下简称 **RCPU**）

## 8.2 CPU 子系统

### 简介

K1 的 **CPU 子系统** 包含以下组件：

- 两个 X60™ 集群
- 一个缓存一致性单元（Cache Coherency Unit）
- 一个用于配置的 Dragon CIU
- 其他用于保障高性能和系统效率的功能模块

### 特性

- **X60™ 集群**

  - 每个集群包含 4 个核心，并集成 512KB 的 L2 缓存
  - BOOST 集群额外集成 512KB 的 TCM
  - 每个 X60™ 核心包含 32KB 的 L1 指令缓存（L1-I）和 32KB 的 L1 数据缓存（L1-D）

- **缓存一致性单元（Cache Coherency Unit）**

  - 维护 X60™ 集群之间的数据一致性

- **Dragon CIU 寄存器**

  - 提供多组配置寄存器，用于配置 X60™ 集群和核心

- **通用计数器寄存器（Generic Counter Register）**

  - SoC 级计数器寄存器

#### FAB_TIMEOUT_CTRL_X_REG

该寄存器用于控制 Fabric#1 S2 端口上 AXI 总线监控器的超时行为。

若 AXI Fabric#1 S2 端口存在挂起请求且持续时间超过设定的超时值，则会触发超时中断。具体说明如下：

- 可通过向 `TIMEOUT_VAL` 写入 `0` 来解除中断；
- 默认超时值为 `0xC000`，每单位对应一个 AXI 时钟周期。

> **注：**
>
> - 仅监控 Fabric#1 S2 端口，此功能专用于调试目的；
> - 为确保在 Fabric#1 S2 端口发生超时时仍能可靠访问寄存器，这些超时控制寄存器应与 SQU 寄存器一同放置于 Fabric#1 S4 端口上。

## 8.3 实时 CPU（Real-Time CPU）

### 简介

K1 的 **实时 CPU（Real-Time CPU，RCPU）** 采用 **Nuclei System Technology Co. Ltd.** 设计的 **32 位 RISC-V N308 高效能处理器内核**，主要面向 **物联网（IoT）及低功耗应用场景**。

### 特性

- 支持 **三级流水线（3-stage pipeline）**、**单发射（single-issue）微架构**
- 支持 **RV32I / M / A / F / D / C / P / B 指令扩展**
- 支持 **特权模式（Privileged Mode）**
- 支持低功耗管理机制，包括：
  - 通过 **WFI（Wait For Interrupt）** 和 **WFE（Wait For Event）** 机制进入休眠模式
  - 支持 **两级休眠模式**：浅度休眠（Shallow Sleep）与深度休眠（Deep Sleep）
- 支持 **16KB 数据缓存（D-Cache）**
- 支持 **64 位实时核私有定时器（Real-Time Core-Private Timer，TIMER）**
- 支持 **增强型核级中断控制器（Enhanced Core-Level Interrupt Controller，ECLIC）**，具备以下特性：
  - 支持 RISC-V 架构定义的软件中断、定时器中断和外部中断
  - 支持可配置的中断级别与优先级
  - 支持 **向量化中断处理模式（Vectored Interrupt Processing Mode）**
- 支持 **不可屏蔽中断（Non-Maskable Interrupt，NMI）**
- 支持 **8 个 PMP（Physical Memory Protection）条目**，最小保护粒度为 **4KB**
- 支持 **RISC-V 调试框架（Debug Framework）**

### 功能描述

#### 时钟域

RCPU 内核包含以下 **两个异步时钟域**：

- **主时钟域（Main Clock Domain）**  
  该时钟域驱动 RCPU 中的大部分功能逻辑，包括：
  - **rcpu_clk**：作为 RCPU 主时钟域的主要工作时钟，驱动 RCPU 内部的核心逻辑，在休眠模式下会自动进行时钟门控（Clock Gating）
  - **rcpu_clk_aon**：始终开启的时钟（Always-On Clock），用于驱动 RCPU 中的常开逻辑，包括 **DEBUG**、**ECLIC** 和 **TIMER**

- **JTAG 时钟域（JTAG Clock Domain）**  
  该时钟域用于驱动 DEBUG 单元中的 JTAG 相关逻辑，包括：
  - **tck_s**：JTAG 内部生成的时钟，由 **jtag_TCK** 时钟经 **3 分频**产生

如上所述，这两个时钟域彼此 **异步**。为保证系统的正确运行，RCPU 内部实现了 **跨异步时钟域处理机制（Asynchronous Cross-Clock Domain Process）**。

##### TIMER

###### 简介

TIMER 用于在 RCPU 内核中产生 **定时器中断** 和 **软件中断**。TIMER 寄存器的详细配置信息请参见 **第 8.4.3 节**，其主要功能说明如下。

###### 时间计数

TIMER 实现了一个 **64 位寄存器（mtime）**，由以下两个寄存器组成：

- **mtime_hi（高 32 位）**
- **mtime_lo（低 32 位）**

用于时间计数。  
默认情况下，**mtime 在复位解除后即被使能并持续计数**。其计数频率的递增由以下两种方式之一控制：

- 内核输入信号 **mtime_toggle_a**
- 或内核的 **常开时钟 rcpu_aon_clk**

###### 定时器中断产生

TIMER 实现了一个 **64 位比较寄存器（mtimecmp）**，由以下两个寄存器组成：

- **mtimecmp_hi（高 32 位）**
- **mtimecmp_lo（低 32 位）**

用于将 **mtime** 的值与 **mtimecmp** 的值进行比较，以决定是否产生定时器中断。具体行为如下：

- 当 **mtimectl.CMPCLREN = 1** 时，若 **mtime** 的值大于 **mtimecmp**，则 **mtime 会被自动清零**，随后定时器从零重新开始计数
- 当 **mtimectl.CMPCLREN = 0** 时，**mtime** 将继续正常递增。软件可通过修改 **mtimecmp** 或 **mtime** 的值来清除定时器中断，从而保证 **mtimecmp** 的值大于 **mtime**

> **说明：** 定时器中断连接至 **ECLIC**，由其进行统一的中断管理。

###### 软件中断产生

TIMER 实现了一个寄存器 **msip**，用于产生软件中断。根据 **第 8.3.4.3.9 节**中给出的寄存器配置说明，仅 **最低有效位（LSB）** 对该功能有效，其行为如下：

- 软件写 **1** 以产生软件中断
- 软件写 **0** 以清除软件中断

> **说明：** 软件中断同样连接至 **ECLIC**，进行统一的中断管理。

###### 软件复位请求产生

TIMER 实现了寄存器 **msftrst**，用于产生 **软件复位请求**。根据后文 **第 9.3.4.3.7 节** 中的寄存器配置说明，仅 **最高有效位（MSB）** 对该功能有效，其行为如下：

- 软件写入 **0x80000A5F** 以产生软件复位请求（该特定写入值用于防止软件随机误写导致的误操作）
- 该寄存器只能通过复位清除（当 SoC 响应软件复位请求并对内核执行复位时，**msftrst** 寄存器将被复位并清零）

> **说明：** 内核通过输出信号 **sysrstreq**（高电平有效）发起软件复位请求。SoC 在响应该请求时，应通过拉低 **rcpu_reset_n** 对内核进行复位，而不是使用 **por_reset_n**。

##### ECLIC

###### 简介

在实时系统或微控制器类应用中，**快速的中断处理机制**至关重要。为此，RCPU 集成了 **增强型核级本地中断控制器（Enhanced Core Local Interrupt Controller，ECLIC）**。ECLIC 是在 RISC-V 标准 **CLIC** 基础上的优化版本，用于统一管理所有中断源，其特点如下：

- **ECLIC 仅服务于单个处理器内核**，并作为内核私有模块运行
- 通过将 CSR 寄存器 **mtvec** 的 **最低有效位（LSB）** 配置为 ECLIC 模式，可使能 ECLIC
- **ECLIC 在功能上与 PLIC 互斥**
- ECLIC 用于管理多个内部和外部中断源，向内核发出中断请求，并支持 **中断抢占（Interrupt Preemption）**

**[ECLIC 寄存器](#eclic-registers)** 的详细配置信息见相关章节，其核心功能说明如下。

###### 中断目标（Interrupt Target）

当 ECLIC 使能后，它对各类中断源进行仲裁，并通过一条专用信号线将中断请求发送至处理器内核（即中断目标），如下图所示：

###### 中断源 ID（Interrupt Source ID）

ECLIC 为每一个中断源分配唯一的 **中断 ID**，最多支持 **64 个中断源**，其分配规则如下：

- **ID 0–18**：保留给内核指定的内部中断  
  - 其中，**ID 3** 固定用于 **软件中断**
  - **ID 7** 固定用于 **定时器中断**
- **ID 大于 18**：可由用户用于连接外部中断源

| ECLIC 中断 ID | 功能 | ECLIC 中断源说明 |
|---------------|------|------------------|
| 0             | 保留 | 未使用 |
| 1             | 保留 | 未使用 |
| 2             | 保留 | 未使用 |
| 3             | 软件中断 | 由 TIMER 产生的软件中断 |
| 4             | 保留 | 未使用 |
| 5             | 保留 | 未使用 |
| 6             | 保留 | 未使用 |
| 7             | 定时器中断 | 由 TIMER 产生的定时器中断 |
| 8–18          | 保留 | 未使用 |

###### 中断级别与优先级（Interrupt Level & Priority）

如 **[中断目标](#interrupt-target)** 所示，**ECLIC** 的每一个中断源均可配置对应的 **中断级别（Level）** 和 **中断优先级（Priority）**。其关键机制说明如下。

- 每个中断源对应的 **clicintctl** 寄存器宽度为 **8 位**，但硬件实际实现并生效的位数由 **clicinfo** 寄存器中的 **CLICINTCTLBITS** 字段决定。

  **【示例】** 若 **clicinfo.CLICINTCTLBITS = 6**，则表示 **clicintctl** 寄存器中仅 **高 6 位** 为有效位，**低 2 位** 固定为常量 **1**，如下图所示。

  > **说明：**  
  > **CLICINTCTLBITS** 字段为只读常量，软件无法修改，其合法取值范围为 **2 ≤ CLICINTCTLBITS ≤ 8**。

- **clicintctl** 寄存器中的有效位被划分为以下两个动态字段：
  - **中断级别（Interrupt Level）字段**
  - **中断优先级（Interrupt Priority）字段**

  其中，**中断级别字段的位宽由 `cliccfg.nlbits` 定义**。

  **【示例】** 若 **cliccfg.nlbits = 4**，则表示 **clicintctl** 有效位中的 **高 4 位** 用于表示中断级别，其余的低位有效位用于表示中断优先级，如下图所示。

  > **说明：**  
  > **cliccfg.nlbits** 字段为可读可写，软件可对其进行配置。

  <img src="static/cliccfg.nlbits.png" alt="" width="500">

**关于中断级别（Interrupt Level）：**

- 中断级别值采用 **左对齐（Left-Aligned）** 的方式进行读取。除由 **cliccfg.nlbits** 定义的有效位之外，其余无效的低位均填充为常量 **1**。具体规则如下：
  - 若 **cliccfg.nlbits > clicinfo.CLICINTCTLBITS**，即 **nlbits** 指定的位数超过 **clicintctl** 实际实现的有效位数，则超出的位全部填充为常量 **1**
  - 若 **cliccfg.nlbits = 0**，则中断级别被视为一个固定值 **255**
  - **中断级别数值越大，对应的优先级越高**
- **中断抢占（Interrupt Preemption）**：  
  高级别中断可以抢占低级别中断。当存在多个中断同时处于挂起状态（**IP = 1**）时，**ECLIC** 会进行仲裁，以确定需要发送至内核的中断源。其中，各中断源的 **级别值** 是仲裁过程中的关键因素之一。

  中断级别值的解码示例如下图所示：

  <img src="static/level_value.png" alt="" width="700">

**关于中断优先级（Interrupt Priority）：**

- 中断优先级值同样采用 **左对齐** 的方式进行读取。除由  
  **`clicinfo.CLICINTCTLBITS - cliccfg.nlbits`**  
  定义的有效位之外，其余无效的低位均填充为常量 **1**。
- **中断优先级数值越大，对应的优先级越高**

  > **说明：**  
  > 中断优先级 **不会影响中断抢占行为**。即，一个中断是否能够抢占另一个中断，与其优先级值无关，仅与中断级别有关。

- 当多个中断同时处于挂起状态时，**ECLIC** 需要进行仲裁以决定将哪个中断发送至内核。该仲裁过程将 **同时考虑中断级别和中断优先级** 两个因素。

#### 控制与状态寄存器（Control & Status Registers，CSRs）

RISC-V 架构中定义了一组 **控制与状态寄存器（CSRs）**，用于配置处理器运行行为或记录执行状态，其说明如下：

- CSRs 是位于内核内部的寄存器，采用 **12 位编码空间** 对其进行访问
- 针对 **数据缓存控制与维护（D-Cache Control and Maintenance，CCM）** 操作，定义了扩展 CSR 寄存器，支持以下功能：
  - **FLUSH（刷新）**
  - **INVAL（失效）**
  - **LOCK（锁定）**
  - **UNLOCK（解锁）**

  上述操作既可以针对 **指定地址（ADDR）** 执行，也可以对 **全局范围（ALL）** 生效。

#### 性能监控（Performance Monitor）

RISC-V 架构定义了以下两类性能计数器：

- **周期计数器（Cycle Counter）**：
  - 为 **64 位时钟周期计数器**，用于统计内核已执行的时钟周期数。只要内核的 **rcpu_clk_aon** 处于开启状态，该计数器就会持续递增
  - CSR **mcycle** 反映该计数器的低 32 位，而 CSR **mcycleh** 反映其高 32 位

- **指令退休计数器（Instruction Retirement Counter）**：
  - 为 **64 位计数器**，用于统计内核成功执行（退休）的指令数量。每成功执行一条指令，该计数器即递增一次
  - CSR **minstret** 反映该计数器的低 32 位，而 CSR **minstreth** 反映其高 32 位

**周期计数器** 与 **指令退休计数器** 通常用于性能评估与分析。

默认情况下，计数器在复位后从 **0** 开始，并持续递增。为降低功耗，在定制 CSR **mcountinhibit** 中提供了额外控制位，当无需进行性能监控时，可通过该位 **暂停计数器运行** 以节省功耗。

#### 低功耗机制（Low-Power Mechanism）

RCPU 内核的低功耗机制工作方式如下：

- 当内核主功能单元处于空闲状态时，其对应的时钟将被 **自动门控（Clock Gating）**，以降低静态功耗
- 内核通过 **WFI（Wait For Interrupt）** 和 **WFE（Wait For Event）** 机制，支持不同的休眠模式（**浅度休眠模式** 与 **深度休眠模式**），以进一步降低动态功耗和静态功耗

#### 时钟控制（Clock Control）

根据唤醒源的不同，区分以下两种情况：

- **内核等待中断唤醒的情况**  
  由于内核只能处理并响应由 **ECLIC** 仲裁和分发的中断，因此，**仅当中断被使能，且其中断级别高于中断阈值等级时，才能唤醒内核**。此外，内核内部 **rcpu_clk_aon** 的使能需要特别注意：

  - **TIMER** 由 **rcpu_clk_aon** 驱动。若 SoC 系统关闭了常开时钟 **rcpu_clk_aon**，则 **TIMER** 因无工作时钟而无法产生定时器中断或软件中断，内核也将无法被唤醒
  - **ECLIC** 同样由 **rcpu_clk_aon** 驱动。若 SoC 系统关闭了常开时钟 **rcpu_clk_aon**，则外部中断信号必须 **保持为有效状态**，直到 SoC 重新使能 **rcpu_clk_aon**。否则，由于 ECLIC 无法在无时钟的情况下采样外部中断信号，内核将无法被唤醒

- **内核等待事件或 NMI 唤醒的情况**  
  当内核通过 **rcpu_clk_aon** 采样到输入信号 **rx_evt**（表示有事件发生）或输入信号 **nmi**（表示发生不可屏蔽中断）时，内核将被唤醒。此时，同样需要谨慎处理 **rcpu_clk_aon** 的使能问题：

  - 若 SoC 系统关闭了常开时钟 **rcpu_clk_aon**，则输入信号 **rx_evt** 或 **nmi** 必须 **保持为 1**，直到 SoC 打开 **rcpu_clk_aon**。否则，由于采样逻辑无工作时钟，内核将无法采样到 **rx_evt** 或 **nmi** 信号，从而无法被唤醒

#### 物理内存保护（Physical Memory Protection）

由于 RCPU 是一款面向微控制器的低功耗内核，**不支持内存管理单元（MMU）**，因此所有地址访问操作均基于 **物理地址**。为了根据物理地址范围及执行特权模式实现内存访问保护与隔离，RISC-V 标准架构定义了 **物理内存保护（Physical Memory Protection，PMP）** 机制。

RCPU 的 PMP 配置特性如下：

- 支持 **8 个 PMP 条目**，最小保护粒度为 **4KB**
- 支持 **PMP TOR（Top of Range，范围上限）模式**

## ECLIC 寄存器（ECLIC Registers）

### 简介（Introduction）

**ECLIC** 寄存器的**基地址（Base Address）**为：

```
0xE002_0000
```

ECLIC（Enhanced Core Local Interrupt Controller）用于管理核心私有的中断源，其寄存器模型与 RISC-V CLIC 架构保持一致，并在实现上进行了增强与优化。

### cliccfg

**cliccfg** 为全局配置寄存器，用于配置 ECLIC 的工作模式，软件可对其进行写操作。

**偏移地址（Offset）：0x0000**

| 位域  | 字段名      | 类型 | 复位值 | 说明                                                          |
| --- | -------- | -- | --- | ----------------------------------------------------------- |
| 7:5 | Reserved | R  | N/A | 保留位，读取为 0                                                   |
| 4:1 | nlbits   | RW | 0x0 | 用于指定 `clicintctl[i]` 寄存器中**中断级别（level）与优先级（priority）字段**的位宽 |
| 0   | Reserved | R  | N/A | 保留位，读取为 1                                                   |

### clicinfo

**clicinfo** 为全局参数寄存器，用于向软件报告 ECLIC 的硬件能力和实现信息，仅支持读取。

**偏移地址（Offset）：0x0004**

| 位域    | 字段名            | 类型 | 复位值 | 说明                                   |
| ----- | -------------- | -- | --- | ------------------------------------ |
| 31:25 | Reserved       | R  | N/A | 保留位，读取为 0                            |
| 24:21 | CLICINTCTLBITS | R  | N/A | 指示 `clicintctl[i]` 寄存器中**实际实现的有效位宽** |
| 20:13 | VERSION        | R  | N/A | 硬件实现版本号                              |
| 12:0  | NUM_INTERRUPT  | R  | N/A | 硬件所支持的中断源数量                          |

### mth

**mth** 用于设置**目标中断阈值级别（Interrupt Threshold Level）**，软件可对其进行写操作。

**偏移地址（Offset）：0x000B**

| 位域  | 字段名 | 类型 | 复位值 | 说明                                                                        |
| --- | --- | -- | --- | ------------------------------------------------------------------------- |
| 7:0 | mth | RW | N/A | 目标中断阈值寄存器。<br/>**说明：** 仅当 ECLIC 最终仲裁出的中断级别**高于**该寄存器中的阈值时，中断请求才会被送往处理器核心。 |

### clicintip[i]

**clicintip[i]** 为中断源的**挂起标志寄存器（Pending Flag Register）**。

**偏移地址（Offset）：0x1000 + 4 × i**

| 位域  | 字段名      | 类型 | 复位值 |说明                                                                              |
| --- | -------- | -- | --- | ------------------------------------------------------------------------------- |
| 7:1 | Reserved | RO | N/A | 保留位，读取为 0                                                                       |
| 0   | IP       | RW | 0x0 | 中断源挂起标志：<br/>- 0：中断未触发<br/>- 1：中断已触发<br/><br/>**说明：** 对于边沿触发型中断源，IP 位可能由硬件自动清除。 |

### clicintie[i]

**clicintie[i]** 为中断源的**使能寄存器（Interrupt Enable Register）**。

**偏移地址（Offset）：0x1001 + 4 × i**

| 位域  | 字段名      | 类型 | 复位值 | 说明                                  |
| --- | -------- | -- | --- | ----------------------------------- |
| 7:1 | Reserved | R  | N/A | 保留位，读取为 0                           |
| 0   | IE       | RW | 0x0 | 中断使能位：<br/>- 0：中断源被屏蔽<br/>- 1：中断源使能 |

### clicintattr[i]

**clicintattr[i]** 用于描述中断源的**触发属性与向量模式**，软件可对其进行写操作。

**偏移地址（Offset）：0x1002 + 4 × i**

| 位域  | 字段名      | 类型 | 复位值 | 描述                                                                                                                                                                                                                                    |
| --- | -------- | -- | --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 7:6 | Reserved | R  | N/A | 保留位，读取为 `2'b11`                                                                                                                                                                                                                       |
| 5:3 | Reserved | R  | N/A | 保留位，读取为 0                                                                                                                                                                                                                             |
| 2:1 | trig     | RW | 0x0 | 中断触发方式配置：<br/>- `2'b00`：电平触发中断。IP 位实时反映中断源电平状态；软件写 IP 被忽略，仅能通过中断源撤销来清除。<br/>- `2'b01`：上升沿触发中断；软件可写 IP 位进行置位或清除。<br/>- `2'b11`：下降沿触发中断；软件可写 IP 位进行置位或清除。<br/><br/>**说明：** 为提升中断处理效率，当中断被接收并跳转至 ISR 时，ECLIC 硬件会自动清除 IP 位，ISR 中无需软件显式清除。 |
| 0   | shv      | RW | 0x0 | 中断向量模式选择：<br/>- 0：非向量模式（Non-Vectored），处理器跳转至共享中断入口地址。<br/>- 1：向量模式（Vectored），处理器直接跳转至向量表中对应中断源的入口地址。                                                                                                                                  |
### clicintctl[i]

**clicintctl[i]** 为中断源控制寄存器，用于配置**中断级别（level）**与**中断优先级（priority）**。
其中，level 与 priority 字段的位宽由 **cliccfg.nlbits** 动态决定。

**偏移地址（Offset）：0x1003 + 4 × i**

| 位域                                          | 字段名      | 类型 | 复位值 | 说明                                              |
| ------------------------------------------- | -------- | -- | --- | ----------------------------------------------- |
| 7 : 7 − (nlbits − 1)                        | Level    | RW | N/A | 中断源级别（Interrupt Level）；数值越大，在 ECLIC 仲裁中级别越高。    |
| 7 − (nlbits − 1) : 7 − (CLICINTCTLBITS − 1) | Priority | RW | N/A | 中断源优先级（Interrupt Priority）；数值越大，在同级别中断仲裁中优先级越高。 |
| 7 − (CLICINTCTLBITS − 1) : 0                | Reserved | RO | N/A | 保留位，读取为 1                                       |
