# 11. 存储与内存（Memory & Storage）

## 11.1 概述

K1 支持片上存储资源，并通过多种外设接口连接不同类型的存储器器件，例如 DDR 以及 NAND/NOR Flash。

## 11.2 片上存储（On-Chip Memory）

### 简介

K1 集成了以下片上存储类型：

- 128KB 启动只读存储器（Boot ROM）
- 256KB 由主 CPU 与实时 CPU 共享的 SRAM

## 11.3 DDR

### 简介（Introduction）

DDR 控制器采用了先进的体系结构设计，通过对访问请求进行**重排序**而非按原始顺序处理，从而显著提升 DRAM 访问效率。该控制器使用**重排序缓冲区（ROB, Re-Ordering Buffer）**对发往存储器设备的访问进行重新组织，以提升整体性能；同时，对于 AXI 接口上具有相同 ID 的事务，仍然严格保持其原始事务顺序不变。

此外，DDR 控制器内部集成了**统一写缓冲池（Unified Write Pool）**，用于临时存储写事务。该写缓冲池能够有效降低写访问延迟，并减少 DRAM 接口在读写切换过程中带来的性能损失。结合**内建的启发式写缓冲控制机制**以及**用户可编程的写缓冲控制策略**，DDR 控制器可以在运行过程中动态平衡读写操作的性能，实现实时优化。

DDR 控制器同时支持 **AMBA AXI4 总线协议**，具有良好的可扩展性，最多支持 **4 个 AXI 端口**。

### 特性（Features）

- 基于优先级的仲裁机制，并具备防止请求饥饿（starvation prevention）的设计
- 通过写缓冲区合并对同一地址的写操作，减少 DDR 写访问流量
- 写缓冲区中的读请求可直接转发至 ROB，而无需实际访问 DDR
- 两级动态调度机制，并支持带宽保障
- 支持多种省电特性，包括：
  - 激活 / 预充电掉电（Active / Pre-charge Power-off）
  - 自刷新（Self-Refresh）
  - 省电模式可通过空闲定时器自动控制、寄存器手动控制或专用端口外部控制
- 支持动态频率切换（Dynamic Frequency Change）
- 支持符合 JEDEC 标准的 LPDDR3 与 LPDDR4 存储器
- 支持 64MB 至 16GB 容量范围的 DRAM
- 单 DRAM 通道，配备 x32 DDR PHY，可通过软件配置为 x32、x16 或 x8 数据位宽
- 支持 x16、x32 DRAM 器件（每 8 个 DQ 对应 1 个 DQS）
- 每通道最多支持 2 个片选（CS）或 Rank
- 对于 LPDDRx，每个 CS 最多支持 8 个 Bank
- 每个 CS 均可映射到不同的起始地址
- 每个 CS 可配置的容量范围为 8MB 至 16GB
- 支持访问后保持 Bank 打开（无自动预充电）
- 支持突发长度为 8 和 16（依据具体 DDR 类型）
- 支持可编程的地址映射顺序
- 支持在 CS 与数据位宽之间灵活配置 Bank 布局
- 集成内存控制器性能计数器
- 提供用于 RISC-V 独占加载 / 存储访问的全局监控机制
- 支持 DDR 事务的安全访问管理
- 支持频率切换后的寄存器更新机制：通过寄存器表实现硬件触发的顺序化更新

### 功能描述

#### DDR 控制器端口分配

DDR 控制器支持 **4 个 AXI 从端口**，并在这些端口之间进行仲裁。各端口与 DDR 控制器的连接关系如下表所示。

| Port0                         | Port1                         | Port2                     | Port3           |
|------------------------------|-------------------------------|---------------------------|-----------------|
| RISC-V X60 集群和 GPU         | GMAC0、GMAC1 以及<br/>AXI Fabric1 端口 | VPU 和 PCIe PortA/B/C     | Display 和 ISP  |

#### 动态调度

DDR 控制器采用**基于优先级的仲裁机制**，并配合**防饥饿（starvation prevention）方案**，以管理关键访问的时延。

DDR 控制器基于以下因素对事务进行调度：

- 当前 DRAM 页状态
- 事务优先级，该优先级由 AXI 接口上的 **AxQoS[2:0]** 信号决定

AxQoS 的解码方式如下：

- `b100`：CRITICAL
- `b011`：TOP
- `b010`：HIGH
- `b001`：MED（Guaranteed Bandwidth Feature）
- `b000`：LOW

DDR 控制器可以在不同 Bank 之间进行交错访问，以实现对不同 Bank 的流式事务达到 **100% 总线利用率**，从而有效隐藏读写命令之间的预充电（precharge）和激活（activate）开销。

**CRITICAL** 优先级的事务始终会被尽可能快速地处理。该类事务不会检查 DRAM 页状态，并会作为下一个待处理事务执行。然而，当存在多个 **CRITICAL** 优先级事务时，仍会考虑 DRAM 页状态。

当不存在更高优先级事务处于等待状态时，事务才会被服务。如果低优先级事务指向的是一个已经打开的页，则当前的高优先级事务会首先关闭该页。

#### 防饥饿机制

为防止事务发生饥饿，系统引入了**老化（aging）机制**：当事务对应的计数器到期时，其优先级会被提升。用于读池（reading pool）和调度池（scheduling pool）的防饥饿计数器值可通过以下寄存器进行配置：

- RPP 防饥饿控制寄存器（RPP_Starvation_Control）
- Spool 控制寄存器（Spool_Control）

#### 调度算法

DDR 控制器内部实现了调度算法，用于对以下事件赋予不同的权重：

- 与当前事务相关的 DRAM 页状态，具体取决于以下情况：
  - 页已打开
  - 页已关闭
  - 页缺失（该页在另一个 Bank 中处于打开状态）
- CS
- 相同 CS
- 不同 CS

调度器通过对数据进行重新排序，以适配 AXI 的有序模型，从而支持 DRAM 的乱序执行。调度器会综合队列状态和 Bank 状态作出决策，以最大化 DDR 总线带宽的利用率。

#### 端口仲裁（Ports Arbitration）

当采用多端口配置时，DDR 控制器使用 **AXI QoS** 信号在不同 AXI 端口之间进行仲裁。如果各端口具有相同的 QoS 优先级，则采用**轮询（Round-Robin）**仲裁机制。

#### 省电模式（Power-Down Mode）

省电模式会关闭 DRAM 模块上的大多数 I/O 缓冲器，主要包括以下两种模式：

- **预充电省电模式（Precharge Power-Down）**  
  当所有 Bank 均处于关闭状态时进入该模式。如果仍有 Bank 处于打开状态，则在进入该模式之前会先发出 **Precharge-All** 命令。

- **激活省电模式（Active Power-Down）**  
  当至少有一个 Bank 保持打开状态时进入该模式。如果所有 Bank 已经关闭，则激活省电请求的行为等同于预充电省电模式。

与激活省电模式相比，预充电省电模式能够节省更多功耗，但在退出该模式时需要重新打开所有 Bank，这可能会对性能产生一定影响。

省电模式的持续时间受 **自动刷新（Auto-Refresh）周期**限制。如果当前没有数据请求，DDR 内存控制器将唤醒 DRAM，执行一次自动刷新操作，然后再次进入省电模式。

对于 **DDR3**，支持选择**快速退出（Fast-Exit）**或**慢速退出（Slow-Exit）**省电模式，该选项决定在省电期间 DRAM 的 **DLL** 是保持工作状态还是被冻结。

#### 自刷新模式（Self-Refresh Mode）

在自刷新模式下，DRAM 会自动对其各个 Bank 进行刷新，具体说明如下：

- 在单个刷新周期内，**预充电省电模式**与**自刷新模式**在功耗节省方面效果相近，但自刷新模式的退出延迟更长。从较长时间尺度来看，自刷新模式更加高效，因为预充电省电模式需要周期性唤醒并执行自动刷新命令。
- **LPDDR** 和 **DDR3** 支持 **部分阵列自刷新（Partial-Array Self-Refresh，PASR）**，用于控制在自刷新期间需要刷新的 Bank 数量。每个 **Chip Select** 都可以在 **SDRAM Configuration Register** 中单独配置 PASR。
- 由于 PASR 允许部分 Bank 在自刷新期间不进行刷新，软件必须对内存使用情况进行跟踪管理，以避免未刷新的 Bank 中的数据丢失。

#### 自动停钟（Automatic Clock-Stop）

当不存在待处理的 DRAM 操作时，**LPDDR** 允许停止 DRAM 时钟。

**自动停钟（Automatic Clock Stop，ACS）** 独立运行，并且可以与其他省电模式同时使用。

#### 省电控制（Power Saving Control）

DDR 内存控制器支持完整的省电特性，包括 **停钟（Clock Stop）**、**预充电省电（Precharge Power-Down）**、**活动省电（Active Power-Down）**、**自刷新（Self-Refresh）** 以及 **深度省电（Deep Power-Down）**。

省电命令可通过以下三种方式发出：

- **外部控制（External control）**
- **手动触发（Manual issue）**
- **自动触发（Automatic issue）**

省电命令可通过 **用户发起命令寄存器（User-Initiated Command Register）** 手动触发，每个请求仅执行一次。新的请求会将内存控制器从当前省电状态中唤醒。

内存控制器也可以在设定数量的空闲周期后，自动进入省电状态（活动省电或预充电省电）。但 **深度省电模式** 必须手动进入，因为该模式会关闭存储阵列的电源，从而导致内存复位。

#### 动态频率切换（Dynamic Frequency Change，DFC）

DDR 频率切换可以通过 **硬件方式（边界引脚握手）** 或 **软件方式（AHB 编程）** 实现，具体如下：

- **硬件 DFC**

  - 系统需要预先将 DFC 表（预定义的频率切换序列）加载到 SRAM 中。每张表对应一个目标频率（例如：表 1 对应 800 MHz，表 2 对应 300 MHz）。
  - 进行频率切换时，SoC 的 PMU 驱动边界引脚并选择相应的 DFC 表。内存控制器随后自动执行 DFC 序列，并在可以安全切换时钟以及整个流程完成时向 PMU 发送指示信号。

- **软件 DFC**

  - 通过对内存控制器寄存器进行编程来启动 DFC 序列，不依赖 SRAM。
  - 软件需要逐步执行整个序列，并通过轮询方式确认流程完成。

## 11.4 QSPI Flash

### 简介

Quad-SPI 用作外部串行 Flash 设备的接口，最多支持四条双向数据线。

### 特性

- 灵活的序列引擎，支持多种 Flash 厂商设备
- 支持单线、双线和四线工作模式
- DMA 支持通过 AMBA AHB 总线（64 位宽接口）或 IP 寄存器空间（32 位访问）读取 RX 缓冲区数据，并通过 IP 寄存器空间（32 位访问）填充 TX 缓冲区
- 可配置的 DMA 内部循环大小
- 支持十五种中断条件
- 支持对已连接 Flash 设备的存储器映射读访问
- 可编程序列引擎，支持未来命令/协议变更，并能够支持所有现有厂商的命令和操作
- 支持所有类型的寻址方式
- 支持标准 SPI、Fast、Dual、Dual I/O、Quad、Quad I/O 模式
- 最高支持 104 MHz 时钟频率运行

QuadSPI 模块的不同阶段及其 I/O 驱动特性定义如下：

- **IDLE**
  串行 Flash 设备未被选中，且无任何交互。所有 QSPI_DATx 信号均处于非驱动状态。

- **INSTRUCTION**
  串行 Flash 设备被选中，并向串行 Flash 设备发送指令。

- **ADDRESS**
  向设备发送串行 Flash 地址。

  > **Note.** 该阶段并非适用于所有 SFM 命令。

- **MODE**
  向串行 Flash 设备发送模式字节，所有 QSPI_DATx 信号均被驱动。

  > **Note.** 该阶段并非适用于所有 SFM 命令。

- **DUMMY**
  向串行 Flash 设备提供 Dummy 时钟周期。

  > **Note.** 该阶段并非适用于所有 SFM 命令。

- **DATA**
  向串行 Flash 设备发送数据或从串行 Flash 设备接收数据。

  > **Note.** 该阶段并非适用于所有 SFM 命令。

QSPI_CS 和 QSPI_CLK 信号在所有阶段中始终保持驱动状态。

## 11.5 SD/eMMC

### Introduction

SD/eMMC 主控制器是一个硬件模块，作为 SD/eMMC 接口的主机，用于在 MMC、SDIO、SD 卡与内部总线主设备之间进行数据传输。

### Features

- 符合 MMC/eMMC 5.1 规范，支持 Socket 3（eMMC）

- 支持 PIO 模式和 SDMA 模式的数据传输

- 支持 ADMA1 和 ADMA2（64 位地址）数据传输

- 支持 1-bit / 4-bit SD 存储卡和 SDIO

- 支持 1-bit / 8-bit MMC 和 CE-ATA 卡

- 支持 eMMC 卡的 SPI 模式

- eMMC 设备支持以下工作模式：

  - Legacy（最高 26MB/s，1.8V 信号）
  - High-speed SDR（最高 52MB/s，1.8V 信号）
  - High-speed DDR（最高 52MB/s，1.8V 信号）
  - HS200（最高 200MB/s，1.8V 信号）
  - HS400（最高 400MB/s，1.8V 信号）

- SD 设备支持以下工作模式：

  - Default Speed（最高 12.5MB/s，3.3V 信号）
  - High Speed（最高 25MB/s，3.3V 信号）
  - SDR12（最高 25 MHz，1.8V 信号）
  - SDR25（最高 50 MHz，1.8V 信号）
  - SDR50（最高 100 MHz，1.8V 信号）
  - SDR104（最高 208 MHz，1.8V 信号）
  - DDR50（最高 50 MHz，1.8V 信号）

- 支持 SDIO 卡的读等待（read-wait）控制

- 支持 SDIO 卡的挂起 / 恢复（suspend / resume）

- 在卡总线上的所有命令和数据传输中，支持 CRC 的硬件生成与校验

- 支持 Socket 1（SD）的卡插入 / 移除检测

> **Note.** 有关 AXI Fabric 规范的更多信息，请参见以下说明：
>
> - SD AXI 主设备始终产生 INCR 类型突发（AWBURST/ARBURST = 0x1），突发大小为 8 字节（AWSIZE/ARSIZE = 0x3）
> - SD AXI 主设备的突发访问为普通、非安全数据访问（AWPROT/ARPROT = 0x2）
> - SD AXI 主设备不会产生原子访问（AWLOCK/ARLOCK = 0x0）
> - SD AXI 从设备不支持独占、受保护或原子访问，其响应信号始终为 “OKAY”（RRESP/BRESP = 0x0）或 “DECERR”（RRESP/BRESP = 0x2）。当访问不存在寄存器的地址时，将返回 “DECERR” 响应。

#### SD/eMMC 总线协议描述

SD 总线上的通信基于命令和数据比特流，这些比特流由起始位开始，并以停止位结束，具体如下：

- **Command**
  命令是启动一次操作的令牌，由主机发送至卡（或多张卡），通过 SDCMD 线以串行方式传输（1 bit）。

- **Command Response**
  命令响应是被寻址卡对先前接收到的主机命令所返回的应答令牌。由于 SDCMD 为双向信号，命令响应同样通过 SDCMD 线以串行方式传输。

- **Data**
  数据线共有 4 条。数据可以从卡传输至主机，或从主机传输至卡，数据通过 Data 线传输，且这些信号均为双向信号。在 1-bit 模式下，仅使用 SDDATA[0]，其余数据线处于高阻态（Z-state）。

#### 特殊总线事务

##### 读等待命令（Read Wait Command）

在读操作过程中，如果主机无法继续接收更多数据，通常会通过停止时钟的方式来暂停卡侧的数据输出。但这种方式同时也会阻止主机继续发出任何命令。

为避免该限制，引入了 **Read Wait** 命令。该命令允许主机在保持时钟继续运行的情况下暂停读数据传输。该命令在一个数据块结束后发出，从而确保主机在不中断整体通信的前提下对数据流进行管理。

##### 主机与卡交互时序

SD 卡通过专用接口与主机相连，包括独立的 SDCLK、SDCMD 以及 SDDATA[3:0] 信号线。

在 **上电复位、软件复位或新卡插入** 之后，主机与 SD 卡将依次经历以下两个阶段：

- **阶段 1 —— 卡识别阶段（Card Identification Phase）**：

  - 主机在总线上搜索新插入的卡
  - 在该阶段，主机会对所有处于卡识别模式的卡进行复位；已完成识别的卡不会被复位
  - 随后，主机将：

    - 发送命令以验证工作电压范围
    - 识别每一张卡，并请求其相对卡地址（RCA）
    - 通过 **SDCMD 信号线** 分别与每一张卡进行通信（针对 SD 存储卡）
  - 该阶段内的所有数据通信均仅使用 SDCMD 信号线

- **阶段 2 —— 数据传输阶段（Data Transfer Phase）**：

  - 当所有卡均完成识别后，主机进入该阶段，系统已准备好进行数据传输
  - 主机驱动完成 Host Controller 配置后，通过向 Command Register 写入命令（该寄存器最后写入）来启动传输
  - 对于 R1b 类型命令，只要忙信号保持为低电平，Command Inhibit 将一直保持置位
  - 当 Command Inhibit 从 1 变为 0 时，将置位 CMD_COMPLETE

> **Note.** 更多信息请参考 *SD Host Controller Simplified Specification V3.00*

#### 卡检测（Card Detection）

SD/eMMC Host Controller 支持通过 GPIO 电平翻转并结合软件操作实现卡检测（插入 / 拔出）。

卡检测相关功能可通过 **Normal Interrupt Status Enable** 位进行访问。当该功能使能后，如果在卡检测开关输入端检测到逻辑电平变化，将产生中断。为避免误触发，在生成中断之前会对该逻辑变化进行去抖处理。

#### SPI 模式（SPI Mode）

通过设置 Legacy Register（0x10C）中的 `<spi_en>` 字段可使能 SPI 模式。除错误中断处理不同外，其余流程与 SD 模式基本一致。

当 SPI 模式下发生错误时，**Error Interrupt Status Register** 中的 `<spi_err>` 字段将被置位。错误的具体原因可通过 Legacy Register 中的 `<spi_err_token>` 字段进行识别。
